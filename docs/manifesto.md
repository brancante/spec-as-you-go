# Manifesto

1. **Specs are discovered, not decreed.** The first spec is wrong; building is how we find out how.
2. **Spec the next slice, not the whole system.** Everything else is a discovery waiting its turn.
3. **A spec you can't verify is a wish.** Every criterion runs.
4. **Spec and code change together.** Disagreement is a bug.
5. **Quality is continuous.** Security, architecture and performance are checked per slice, in proportion to risk.
6. **Look before you build.** The ecosystem is searched live; "build" must beat "adopt" on evidence.
7. **Spend intelligence where it matters.** Strong models for judgment, cheap ones for mechanics.
8. **Humans decide the irreversible.** Agents run free everywhere else.
9. **Every idea gets a greenfield.** New capabilities start isolated in a cell or lab, so evolution never requires a rewrite.
10. **The product thesis is a spec too.** Differentiation, fit and scale are tested and revised with evidence, like code.
11. **Experience first, engineering second.** Validate the journey with users before hardening the system behind it, and build the prototype so nothing is thrown away.
12. **Overlaps are found early, not in production.** Other owners get a contract and a conversation before they get a surprise.

## How it differs

| | Spec Kit / Kiro | OpenSpec | Superpowers | Spec as you go |
|---|---|---|---|---|
| Spec timing | up front, per feature | per change (delta) | design doc, then plan | per slice, grows from discovery |
| Drift handling | manual | manual | n/a | reconcile + sweep every slice |
| Quality gates | principles in constitution | none | review skills | security/arch/perf per slice |
| Model choice | fixed | fixed | fixed | routed per task |
| Tool discovery | none | none | none | live scout, dated and sourced |

Sources and caveats for the landscape are in the project history; comparisons were drawn from third-party write-ups and should be re-verified.
